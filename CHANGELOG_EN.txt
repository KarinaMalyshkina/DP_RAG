2026-06-01:

1) In-framework dataset loading + 4 controlled corpus variants


GOAL
    Implement loading of a public corpus into the framework and prepare 4
    controlled versions to study the "duplication <-> DP degradation" link:
      (i)   original         — all documents unique (control);
      (ii)  full_duplicate   — a subset of documents repeated verbatim;
      (iii) partial_overlap  — documents share a common sentence/paragraph;
      (iv)  canary           — unique secrets inserted (targets for extraction attacks).

CORPUS CHOICE:
    Loaded the HealthCareMagic-100k dataset (RafaelMPereira/HealthCareMagic-100k-Chat-Format-en).
    A document is built from a single doctor's answer; the patient question is kept in metadata["query"].
    Why not Natural Questions after all: the NQ corpus consists of the whole of Wikipedia, which is very heavy to download locally.
    HCM format: a single text field = "<human>: question\n<bot>: answer", parsed on "<bot>:".

2) Switched the generator model of both DP-RAGs to OLMo-2-7B-Instruct


GOAL
    Move both DP-RAG pipelines (Koga and Grislain) off their default models onto
    a single shared generator model: allenai/OLMo-2-1124-7B-Instruct.
    One model for both pipelines leads to a fair privacy-utility comparison
    (we hold the "generator" variable constant; only the DP mechanism differs).

WHY OLMo-2-7B-Instruct AND NOT Pythia-6.9b
    Grislain's main path (dp_chat / dp_summary in dp_model.py) uses
    tokenizer.apply_chat_template(...) with system/user roles. This requires an
    instruct model with a chat template.
      - Pythia-6.9b — a base model without a chat template, so apply_chat_template fell over;
        Grislain would have to be rewritten to manual prompt formatting.
      - OLMo-2-1124-7B-Instruct — an instruct model with a chat template and
        a clean drop-in for both pipelines at the same scale (~7B).
